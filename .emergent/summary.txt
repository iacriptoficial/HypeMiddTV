<product_requirements>
The user initially requested an application that displays their real-time balance from a Hyperliquid futures account and their connected wallet address to confirm proper exchange connection.

As development progressed, the requirements evolved to address several issues and new features:
1.  **Accurate Balance Retrieval**: The core problem was the app showing a zero balance despite the user having funds. This evolved into a complex task of distinguishing between the agent wallet (private key-derived) and the main trading account where funds are held on Hyperliquid, requiring dynamic discovery of the main account address via API.
2.  **TradingView Webhook Integration**: Implement a public API endpoint to receive webhook signals from TradingView. This endpoint needed to be externally accessible and correctly process various JSON payloads.
3.  **Real Order Execution**: The application must execute real buy/sell orders on Hyperliquid (market or limit) based on the received TradingView signals, rather than just simulating them.
4.  **Order Precision Handling**: Orders frequently failed due to invalid quantity or price formats. The system needed to automatically adjust and round quantities and prices to match Hyperliquid's  (for quantity precision) and  (for price divisibility) requirements.
5.  **UI/UX Improvements**: Enhance the frontend for better user experience, including:
    *   Centralizing error messages in logs instead of top banners.
    *   Implementing infinite scrolling for logs, webhooks, and responses.
    *   Fixing the header to be sticky with dynamic page titles.
    *   Improving the Copy button functionality for webhook URLs.
    *   Adding a Restart Server button in the UI.
    *   Displaying detailed raw JSON payloads in logs for debugging.
    *   Adding a filter for log messages (ERROR/INFO/ALL).
</product_requirements>
